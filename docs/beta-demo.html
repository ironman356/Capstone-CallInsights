Call Insights

An evidence-first workspace that turns mortgage-servicing call transcripts into traceable insight, storytelling, and operational action.

Beta DemonstrationLocal working productOctober 2026
01 · Project description

Help servicing leaders learn from every call—not just the calls they have time to review.

WHO

Mortgage-servicing leaders

Managers and operations teams identifying recurring customer friction and coaching opportunities.

HOW

Evidence, not guesses

Transcripts become structured issues, behaviors, outcomes, sentiment, and evidence-linked patterns.

VALUE

Insight to action

Users move from an issue to a representative call, then into a strategy or story-based intervention.

02 · Beta state

A random user can run the local Beta workflow today.

What works now

  • Explore a populated transcript dataset and ranked issues.
  • Open evidence calls with turns, segments, outcomes, behaviors, and sentiment.
  • Compare approaches and navigate Story Dashboard evidence.
  • Create or advance a persisted action plan; export a report.

What this Beta proves

  • Frontend, FastAPI backend, and pipeline operate end to end locally.
  • The product is valuable before SPS production integration.
  • File-based artifacts provide traceable, repeatable demo data.
  • SPS server and LLM services are planned production integrations, not local Beta dependencies.
03 · Architecture & data flow

One evidence-first workflow—local today, SPS-ready tomorrow.

Local Beta: transcript files → Python analysis → persisted evidence → FastAPI → React workspace. Production: SPS servicing systems, secure server/API, LLM services, governance, and audit trail.

04 · Technology & code layout

Explicit contracts keep the implementation understandable.

Technologies

  • React + TypeScript + Vite for the web workspace.
  • FastAPI + Pydantic for validated API contracts.
  • Python for ingestion, analytics, and report generation.
  • JSON / JSONL for local processed data and strategy state.

Code layout

  • apps/web/src/pages/ — operational tabs.
  • apps/web/src/api.ts — frontend API boundary.
  • apps/api/app/api/ — routes and schemas.
  • apps/api/app/services/rank1/ — pipeline and solution logic.
  • data/raw · processed · outputs — source, evidence, and rollups.
